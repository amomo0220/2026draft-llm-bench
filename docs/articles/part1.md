## この記事でやっていること

10月22日（木）は、2026年のプロ野球ドラフト会議です。

その1週間前に、Claude（Anthropic）、GPT（OpenAI）、Gemini（Google）の3つの AI に、ドラフトの予想をしてもらいました。予想してもらったのは次の3つです。

- 12球団それぞれの1位入札
- 1位で競合しそうな選手
- 千葉ロッテマリーンズの1〜5位

そして、その予想を答えが出る前に公開して、あとから書き換えられない形にしました。ドラフトが終わったら、この予想と実際の結果を突き合わせます。

きっかけは、私の応援する千葉ロッテマリーンズのサブロー監督が、ドラフトや外国人選手の情報収集に AI（Claude Code）を使うと報じられたことです。サブさんが Claude Code でどのモデル（AI の種類）を選んで、どう使うのかは分かりません。でも、私も AI と一緒にドラフトを楽しみたいなと思いました。

いろいろな AI を気軽に使えるようになった今、どの AI がどれくらいドラフトを読めるのか。そして、AI に何を渡せば読めるようになるのか。それを試してみたくなったのです。

## 予想を「封筒に入れて」預けておく

AI の予想を紹介する記事は、結果が出たあとに「AI はこう言っていた」と当たった回だけを取り上げがちです。それだと、本当に当てたのか分かりません。

なので今回は、予想を封筒に入れて封をし、誰かに預けておくような仕組みにしました。

【画像2：事前登録のイメージ図】

```
「予想を封印して、当日に開封する」流れを表す、横長のシンプルな図解イラスト。
左側：ロボットが封筒に紙を入れ、封蝋（シーリングスタンプ）で封をしている。
中央：鍵のかかったガラスケースの中に封筒が保管されている。ケースの横に時計。
右側：同じ封筒が開けられ、中の紙と、野球の結果発表のボードを見比べている。
3つの場面は左から右への矢印でつながっている。
フラットデザイン、紺・白・薄いグレー、差し色に赤。文字は入れない。
```

具体的には、予想のファイルを GitHub（プログラムを公開・管理するサービス）に置いて、公開した時点に「タグ」という目印を付けています。目印のあとで予想のファイルが1文字でも変わると、自動のチェックで引っかかります。目印自体も、動かしたり消したりできない設定にしました。

外れた予想も、そのまま後編で出します。

## AI に何をさせたか

### 3つの AI

使ったのは次の3つです。

- Claude Sonnet 5.5（Anthropic）
- GPT-5.6 Terra（OpenAI）
- Gemini 3.8 Flash（Google）

どれも各社の「真ん中のクラス」のモデルです。1社だけ最上位のモデルを使うと、比べ方が不公平になってしまうので、格と料金帯をそろえました。

### AI に渡すものを3通りに変える

どの AI が当てるかも気になりますが、今回いちばん見たいのは、AI に何を渡すと予想が変わるのかです。そこで同じ AI に、3通りのやり方で予想してもらいました。スカウトにたとえるとこんな感じです。

【画像3：3つの条件のイメージ】

```
横に3コマ並んだ、親しみやすいフラットなイラスト。各コマに同じデザインの小さなロボットのスカウトがいる。
1コマ目：ロボットが机で1冊の名簿（名前の行が並んだ紙）だけを読んでいる。
2コマ目：ロボットがノートパソコンでネット検索をして、メモ帳に書き込んでいる。
3コマ目：ロボットがノートパソコンで調べたあと、虫めがねで名簿とメモを照らし合わせている。
3コマとも同じ背景色（薄い水色）、紺と白を基調に差し色は赤。文字は入れない。
```

- 条件B「名簿だけ」：候補者の名簿だけを渡されたスカウト。名簿には氏名・所属・ポジションが載っています
- 条件C「Web 検索」：ネットで調べられる記者。調べてメモを書き、そのメモから予想を出します
- 条件D「エージェント」：調べたうえで名簿で裏を取るアナリスト。Web で調べて予想を出したあと、出てきた選手を全員、名簿で確かめ直します

名簿は、日本高等学校野球連盟と全日本大学野球連盟が公表しているプロ志望届の提出者一覧をもとに作りました。高校生と大学生は、志望届を出していないと指名できません。なので、AI が志望届を出していない選手の名前を書いたら、「指名できない選手を予想した」と判定できます。

それぞれのやり方 × 3つの AI で3回ずつ、全部で27回予想してもらいました。AI は同じ質問をしても毎回少しずつ違う答えを返すので、1回だけだと「たまたま」と区別がつかないからです。

### 「AI」と「AI を動かす仕組み」は別もの

サブロー監督のニュースが出たとき、ネットでは「Claude Code は AI（モデル）じゃなくて、AI を動かす仕組み（ハーネス）だよ」という声も見かけました。

車でいうと、AI のモデルがエンジンで、ハーネスは車体や運転のしかたです。同じエンジンでも、地図（名簿）を積むか、カーナビ（Web 検索）を付けるかで、たどり着く場所は変わります。今回の3つのやり方は、エンジンはそのままで、車体だけを変えて走らせた比較です。

### 準備中に見つけた、AI のちょっとした「うそ」

本番の前に何度か試したときのことです。

Web 検索ができるやり方で、最初は「調べて、決まった形式（JSON というデータの形）で答えて」と1回で頼んでいました。すると Gemini は、4回試して4回とも一度も検索しませんでした。それなのに、ロッテの予想の「情報源」の欄には URL が6件書かれていました。検索していないので、これは AI が自分で書いた URL ということになります。

そこで、「調べてメモを書く」と「メモを決まった形式に整える」の2回に分けて頼むようにしました。すると3社ともちゃんと検索するようになり、情報源の URL も、調べたメモに実際に出てきたものだけになりました。頼み方を変えるだけで、AI の動きはけっこう変わります。

## 答え合わせでは何を見るか

ドラフト当日に結果が出たら、こんなところを見ていきます。

- 1位入札がいくつ当たったか。12球団のうち、AI が本命にした選手に実際に入札した球団の数です
- 自信の度合いが合っていたか。「70%」と言った予想が、本当に7割くらい当たっているか
- ポジションだけでも当たっていたか。選手は外れても、「投手を取る」という読みは合っていたか
- ロッテの1〜5位が、順位ごとにどれだけ当たったか。5人のうち何人が実際に指名されたか
- 名簿にない選手や、志望届を出していない選手の名前をどれだけ書いたか

やり方ごと、AI ごとに比べて、「何を渡すと当たるようになるのか」を後編でまとめます。
